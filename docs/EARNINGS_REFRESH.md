# 실적 발표값 갱신

실적 공급원의 반영 지연과 하루 한 번 장 마감 배치 때문에 이미 나온 실적도
사이트에서 비어 있을 수 있었다. `earnings-refresh`는 등록된 실적 발표 전후에
5분 간격으로 공개 원문을 확인한다. GitHub 예약과 공급원 지연 때문에 발표 후
5분 안의 반영을 보장하지는 않는다.

기존 예약의 실제 실행 간격이 수 시간 벌어진 기록이 있어 예약만 빠르게 바꾸지
않는다. 확정 발표 6시간 전부터 3시간 뒤까지 아직 발표값이 없으면 이미 시작된
`earnings-watch`가 같은 러너에서 60초마다 확인한다. 최대 5시간 30분 동안 유지하며
새 값·전체 경로 실패·발표 구간 종료 시 반환한다. 새 값은 바로 게시 단계로 넘긴다.
러너 시작과 Pages 배포 지연은 별도로 남으므로 실시간 반영을 보장하지는 않는다.
한 회사의 실적을 게시한 뒤 다른 회사의 확정 발표가 남아 있거나 러너 감시 시간만
소진되면, 해당 발표 구간 안에서 다음 감시 실행을 직접 요청한다. 공식 사이트가
접속을 차단해도 같은 이벤트의 등록된 Nasdaq 경로가 정상인 경우 감시를 이어간다.
실패 경로는 보고서와 로그에서 보존하며 성공으로 바꾸지 않는다. 모든 경로가
실패하면 즉시 중단하고 정기 예약으로 재시도한다. 발표 구간이 끝나면 종료한다.

확정 일정은 발표 24시간 전부터 72시간 뒤까지, 추정 일정은 7일 전후를 확인한다.
Nasdaq EPS는 해당 회계 분기와 실제 발표일을 확인한다. ASML·TSMC는 공식 실적
발표 원문도 별도로 확인하며 전 분기 실적·다음 분기 가이던스를 당기 실적으로
저장하지 않는다. 공식 EPS의 통화·보통주/ADR 단위·기본/희석 기준을 명시한다.
현재 키 없는 수집 대상은 Nasdaq의 미국 상장 종목과 명시된 공식 회사 어댑터다.
한국 종목 코드를 Nasdaq로 보내지 않으며 미지원 이벤트는 보고서에 사유를 남긴다.
예를 들어 ASML의 EUR 보통주 기본 EPS를 USD ADR 컨센서스와 비교해 비트 여부를
판정하지 않는다. 질문 판정과 확률·공식 예측 원장은 이 배치의 대상이 아니다.

`earnings-capture`는 수신 완료 시각과 원문 해시를 가진 불변 묶음만 만든다.
`earnings-apply`는 최신 main에서 다시 파싱·검증한 뒤 표시용 원장에 추가한다.
정정은 `supersedes`가 있는 새 revision이다. 기존 행은 보존하며 더 오래된 캡처로
새 실제값을 되돌리지 않는다. 원문/경로/해시/시간 검증 실패는 전체 추가를 막는다.
일부 공급원 실패 시 검증된 다른 공급원 결과는 보존하고 실패를 명시한다.

의미 있는 값이 바뀐 경우에만 원문과 표시 원장을 커밋하고 Pages를 직접 실행한다.
변경 없는 확인은 커밋·재배포·모델 갱신을 만들지 않는다. 장 마감을 기다리는
`investing-data-writer` 잠금과 분리하고, main이 움직이면 불변 원문을 최신 main의
새 체크아웃에 다시 적용한다. 최대 3회 재시도하며 강제 푸시·이력 수정은 하지 않는다.

수동 실행은 Actions의 `earnings-refresh` → Run workflow를 사용한다. 실패 상태와
보존된 capture/replay 보고서에서 공급원 실패인지 입력 검증 실패인지 확인한다.
화면은 최근 발표 실적과 발표 대기를 구분하고 각 회사의 상세 화면으로 연결한다.

2026-10-15 02:03 UTC 공개 화면 확인에서는 ASML 10월 14일 발표의 공식 EUR 실적이
USD 컨센서스와 분리되어 표시됐고, TSMC는 10월 15일 02:00 ET / 15:00 KST
발표 예정으로 표시됐다. TSMC의 Q3 가이던스는 실제 발표값으로 저장하지 않았다.
이는 당시 배포 확인 기록이며 이후 상태는 최신 캡처 결과로 판단한다. ASML 질문의
기존 예측 확률도 보존하고 동일 통화·주식 단위 확인 전까지 판정 대기로 안내한다.
독립 6개월 전망의 공식 입력 수집은 별도 `daily6m-sources-refresh` 경로이며,
이 실적 표시용 원장과 서로 갱신하지 않는다.
