# 시계열 입력 경량 갱신 배치

기존 일일 배치는 ALFRED 전체 등록 계열, 공식 시장 이력, DFM 캐시, 예측·해소와 검증을 함께 처리했다. 배치 종료 후 공개되는 입력은 다음 수집까지 기다렸고, PR 검증 완료도 V8·Pages 실행을 중복 발화했다. 새 배치는 핵심 입력의 수집과 배포 연쇄를 분리한다.

## 갱신 주기

- GitHub Actions에서 UTC 매시 17분·47분, 약 30분 간격으로 핵심 입력을 확인한다. GitHub 예약은 지연될 수 있으므로 실제 실행 간격을 보장하는 시계가 아니다.
- NASDAQCOM·VIXCLS·DGS2·T10Y2Y·DTWEXBGS의 신규·수정 ALFRED 빈티지를 수집한다. 계열별 성공 시각에 7일 겹침을 적용하며, 실패한 계열의 조회 범위를 다른 계열의 성공으로 앞으로 옮기지 않는다.
- CBOE·당해 Treasury와 최근 30일 FRED 공식 API 시장 자료를 수집한다. 원문·캡처 시각·해시·원래 공개 빈티지를 보존한다. 동일 값의 재수집으로 관측일의 나이를 갱신하지 않는다.
- 기존 일일 전체 자료 복구·거시 계열 수집·DFM 캐시 작업은 유지한다. 경량 배치는 재적합·봉인 평가·워크북을 수행하지 않는다. 새 6개월 예측의 주간 발행 주기도 유지한다.

## 안전한 저장과 연쇄

수집 작업은 원장에 쓰지 않고 키 없는 원문 묶음을 만든다. 짧은 발행 작업이 최신 main의 임시 체크아웃에서 원문 해시·시각·출처를 검사하고 기존 append 도구로 재생한다. 동시 커밋으로 push가 거절되면 새 main에서 같은 원문을 다시 적용한다. 정정은 기존 도구의 supersedes revision으로 남기며 기존 행은 보존한다.

실제 관측 수정 또는 현재 사용할 수 있는 입력 집합·게이트·마감 세션·주차가 바뀐 경우에만 모델 갱신과 Pages 배포를 연결한다. `available_at` 경계를 지난 사실도 변화에 포함한다. 나이 숫자만 증가하거나 같은 응답을 다시 받은 경우에는 전체 모델·검증·배포를 반복하지 않는다. 입력 수집 실패는 기록하고 예측 발행 연쇄를 막으며, 성공 회복은 별도로 감지한다.

경량 배치가 명시적으로 호출한 모델 작업은 검증과 main 저장을 성공한 뒤 Pages 배포도 명시적으로 요청한다. 자동 토큰으로 시작된 작업의 완료 이벤트에만 의존하지 않으며, 저장 실패나 변경 없는 모델 작업은 이 추가 배포를 요청하지 않는다.

## 공개 시점의 한계

빠른 배치가 아직 발표되지 않은 관측값을 만들 수는 없다. H.10 달러지수는 전주 자료를 주간으로 공개하고 연방휴일에는 발표일이 밀린다. H.15·FRED 입력도 각자의 공개 주기를 따른다. ALFRED 날짜 빈티지의 보수적 뉴욕 일말 가용시각과 기존 모델의 신선도 한도는 그대로 유지한다. 따라서 발표·가용시각·필수 입력 검사를 모두 통과해야 예측 그래프가 표시된다.

운영 계약: `data/contracts/timeseries_inputs_refresh.yaml`. 명령은 `timeseries-inputs-capture --out <bundle>`와 `timeseries-inputs-apply --bundle <bundle> --report <report>`이며, `--root`로 배치의 임시 최신 체크아웃을 지정할 수 있다.
