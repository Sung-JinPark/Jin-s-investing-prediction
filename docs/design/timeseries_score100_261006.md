# 시계열 검증 성적 — 100점 환산 설계 (2026-10-06)

**상태**: 적용 (표시 전용). 대상: `#timeseries/backtest` 탭(V8 봉인 성적).
**요청**: 사용자 2026-10-06 — "검증 성적을 어렵게 표현하지 말고 100점 만점으로 직관적으로 환산하고,
오차율 같은 한눈에 이해되는 그래프로 바꿔라. 외부 솔루션·증권사·연구에서 어떻게 표현하는지 벤치마킹해서
정밀 설계 후 적용·배포."

## 1. 무엇을 바꾸고 무엇을 바꾸지 않나

| 바꾸는 것 (표시 계층) | 바꾸지 않는 것 |
|---|---|
| 검증 탭 첫 화면: 100점 점수판 → 오차 비교 → '10번 중 8번' 그림 → 실전 승패표 | 모델 코드·계약 yaml·봉인 원장·라이브 원장(1바이트 무변경) |
| 기존 상세 차트 5종·KPI·봉인 판정은 '전문가용 상세 지표' 접힘 안으로 이동(삭제 없음) | 게이트 판정(표시 게이트 = 전체창 `gate_pass`), 확률, 경로 |
| 빌더가 공개 개선율의 분자·분모(절대 CRPS)와 라이브 확정 행을 함께 싣는다 | R8-D4 비공개 목록(방향 적중률·MASE·RMSE·pinball·width·first_touch·distribution_selection) |

점수는 `timeseries_v8_display.score100()`이 **이미 공개된 값만으로 고정 규칙**을 적용해 계산한다.
학습·적합·최적화가 아니며, 화면은 재계산하지 않고 그대로 그린다. 점수는 게이트가 아니고 매매 신호가 아니다.

## 2. 벤치마크 — 다른 곳은 어떻게 보나

| 출처 | 표현 방식 | 가져온 것 |
|---|---|---|
| 기상예보 검증 CRPS Skill Score (CRPSS = 1 − CRPS/CRPS_ref; 0 = 기준선과 동급) — [solarforecastarbiter](https://solarforecastarbiter-core.readthedocs.io/en/latest/generated/solarforecastarbiter.metrics.probabilistic.crps_skill_score.html), [climpred](https://climpred.readthedocs.io/en/v2.1.2/api/climpred.metrics._crpss.html) | 기준선 대비 상대 오차 | 정확도 축 = 공개된 `crps_improvement_vs_best` 그대로 |
| M4 예측대회 OWA (Naive2 오차 = 1로 정규화) — [M4](https://mofc.unic.ac.cy/m4/) | "기준선 오차를 100으로 볼 때" | 오차 지수(기준선=100) 표기, 오차 막대 쌍 |
| Amazon Forecast 예측기 평가 (백테스트 창별 wQL·WAPE·coverage) — [AWS 문서](https://docs.aws.amazon.com/forecast/latest/dg/metrics.html) | 분위수 손실 + 구간 적중률 병기 | 정확도와 '약속 지킴'(coverage)을 별도 축으로 |
| TipRanks Smart Score (8요인 균등 가중 → 1~10점, 1~3/4~7/8~10 세 구간 라벨) — [TipRanks](https://www.tipranks.com/news/labs/measure-stock-potential-with-tipranks-smart-score) | 다요인 고정 가중 합산 + 구간 라벨 | 5축 고정 가중 100점 + A/B/C/D 등급 |
| 구간예측 신뢰도 진단 (공칭 80% 구간의 실제 적중률) | "10번 중 몇 번" | 도수 픽토그램 |

증권사·핀테크 앱이 흔히 쓰는 '방향 적중률'은 **의도적으로 제외**했다 — R8-D4가 매매 신호로 소비될
위험 때문에 비공개로 정했고, 50% 안팎 값이 '실력'처럼 읽힌다. 라이브 승패도 방향이 아니라 오차(CRPS)로 센다.

## 3. 점수 규칙 (v1, `method: display_only_fixed_rule_v1`)

총점 = Σ(항목 점수 0~100 × 가중) / 100, 반올림. 모든 입력은 **봉인창(2019+, 385원점)** 과 라이브 원장.
봉인창 블록이 없으면 점수 없음 — 개발기간이 섞인 전체창으로 대체하지 않는다(fail-closed).

| 항목 | 가중 | 입력 | 매핑 |
|---|---|---|---|
| 정확도 | 30 | 4기간 `crps_improvement_vs_best` | 기간별 50 + 500×개선율, [0,100] 클램프 후 평균. 0% = 50, +10% = 100, −10% = 0 |
| 확실성 | 10 | `loss_diff_ci90`, 기간별 DM p | 21+63일 CI90 상한 < 0 이면 50 + (p<0.05 기간 비율)×50 |
| 약속 지킴 | 30 | 80%·50% 구간 적중률 × 4기간 (8검사) | 100 − 25×│편차pp│/허용폭. 허용폭 = 계약 dev_gate_proxy(80%: 4pp, 50%: 5pp) → 대역 끝 75점, 4배 0점 |
| 위기 대응 | 15 | 국면 3종 80% 적중률 | 허용폭 10pp(발행 하한 70% = 75점), 과잉 적중(보수적)은 벌점 ½. **원점 0개 = 0점** |
| 실전 성적 | 15 | 라이브 확정 행 | 승률·적중률을 가상 10행(승률 50%·적중 80%)으로 수축 후 [승률×100, 적중 매핑]의 평균 |

등급: 80+ A 우수 · 60~79 B 보통 · 40~59 C 미흡 · <40 D 부진.

**앵커 선택의 이유**
- 정확도 만점을 +10%에 둔 것: 효율적 시장의 수익률 분포 예측에서 단순 기준선 대비 개선은 한 자릿수 %가
  현실적 상한이라는 이 저장소의 실측(V9~V13 트랙 다수 0%대 채택 실패, V8 봉인창 +1.2~+4.9%)에 맞춘 설계
  선택이다. 문헌 근거를 주장하지 않는다 — 앵커는 공시하고 고정한다.
- 약속 지킴의 허용폭은 새로 만들지 않고 계약의 dev_gate_proxy 대역을 그대로 썼다.
- 검증 표본이 없는 위기(2008)를 0점으로 둔 것은 '증거 없음 = 점수 없음' 원칙(봉인 판정 '보류'와 같은 이유).
- 라이브 수축(사전 10행)은 2전 2승 같은 소표본이 점수를 튀게 하지 않기 위한 고정 규칙(학습 아님).

## 4. 2026-10-06 실측 결과

70점 · B 보통 — 정확도 19.2/30 · 확실성 6.2/10 · 약속 지킴 27.2/30 · 위기 대응 8.6/15 · 실전 8.8/15.
읽는 법: 기준선보다 일관되게 조금 덜 틀리고(오차 −1.2~−4.9%), '10번 중 8번' 약속은 거의 정확히
지키지만(7.7~8.2번), 통계적으로 확실한 기간은 1개뿐이고 2008급 위기와 실전 표본이 비어 점수가 깎인다.

## 5. 화면 구성 (위→아래)

1. **점수판** — 원형 게이지(총점), 등급 칩, 4구간 눈금 막대, 5축 막대(점수/가중), 축별 한 문장, '점수는 어떻게 매기나요?' 접힘.
2. **얼마나 틀렸나** — 기간별 평균 예측 오차(CRPS, 수익률 %p) 막대 쌍. 줄인 오차는 빗금, 우측에 −x% + 오차 지수.
3. **'10번 중 8번' 약속을 지켰나** — 기간별 10점 픽토그램(부분 채움), 8번째 칸 테두리 = 약속선.
4. **실전 승패표** — 라이브 확정 행별 승/패 타일(기준선 대비 오차 ±%, 범위 적중 여부).
5. **전문가용 상세 지표**(접힘) — 기존 봉인 리드·KPI·판정·CRPS 개선율·적중 편차·순위 빈도·국면별·표·전진 카드.

HTML/CSS로 그렸다(SVG viewBox 글꼴 확대 금지 규약 — 모바일 390px에서 가로 넘침 0 확인).
