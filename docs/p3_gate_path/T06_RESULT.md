# T06 — 정지 규칙과 부정 결과 선언 (2026-09-11)

## 1. 왜 지금 박아두는가

부정 선언은 늦게 정할수록 안 하게 된다. 20문항에서 성적이 나쁘면 "표본이 얇다"고 하고,
30문항에서 나쁘면 "이번 분기가 특이했다"고 하고, 49문항에서 나쁘면 "한 건만 더"라고 한다.
계약 `stopping_rules` 가 문턱과 조건을 결과 보기 전에 고정한 이유이고, T06 은 그 조건을
**사람이 다시 해석할 여지 없이** 계산한다.

## 2. `src/ai_fc/gate_review.py` — 중간검토와 부정 선언

문턱·조건은 전부 계약에서 읽는다. 계약을 못 읽으면 페일클로즈 기본값을 쓰되 **통과 쪽으로
기울지 않는다**(문턱 20·30, 부정 선언 30문항 ∧ CI90 하한 > 0.20).

부정 선언은 **두 조건의 논리곱**이다 — 문항 수 하나만으로도, CI 하한 하나만으로도 발동하지 않는다.

현재 상태 (2026-09-11):

```
게이트 상태 표현 : 미결 (0.33 SE)
해소 문항        : 7/50
행 평균 (정본)   : 0.15986
문항 등가중      : 0.220793
클러스터 CI90    : [0.06894, 0.31583]
중간검토 문턱    : 20, 30 (도달 없음)
부정 선언 조건   : 문항 30+ ∧ CI90 하한 > 0.2
판정             : 문항 7 — 다음 중간검토 문턱 20
```

리포트 본문(`--markdown`)은 두 단위 · 도메인 분해 · 손실 3분해 · 예약 손실 시나리오 ·
계약이 금지한 것 · 부정 선언 조건 충족 여부를 담는다. 부정 선언이 발동하면 같은 템플릿이
**판정서**로 전환되며 원인 분해(§3 세 조각의 비중)와 재도전 조건(새 포트폴리오 계약 v2 를
결과 전에 커밋, 이 표본 재사용 금지, 자금 결정 경로 영구 차단 유지)을 적는다.

도메인 분해가 지금 말해주는 것:

| 도메인 | 행 | 문항 | Brier |
|---|---|---|---|
| macro | 5 | 3 | 0.19450 |
| earnings | 3 | 2 | **0.02817** |
| market-daily | 2 | 2 | 0.27080 |

**상태 파일을 만들지 않는다.** 리포트는 stdout 으로만 낸다 — 손으로 갱신하는 상태 파일은
낡으면 잘못된 다음 행동을 부른다(테스트로 고정: 세 파일 모두 쓰기 호출 0).

## 3. `src/ai_fc/gate_guard.py` — 금지 행위 감지기

계약 `stopping_rules.never` 세 항목은 문장으로만 있으면 지켜지지 않는다. 셋 다 **조용히**
일어날 수 있기 때문이다.

| 금지 행위 | 감지 방법 | 테스트 |
|---|---|---|
| `gate_arithmetic_change` | `schema.sql` 의 두 SQL 리터럴 + `config.py` 의 `GATE_P3` 상수 문자 일치 | `< 0.18` → `< 0.20` 으로 바꾸면 잡힌다 |
| (원장 행 삭제) | git 기준선 대비 `ledger.csv` 의 **삭제된 줄** | 행 하나 지우면 잡힌다 |
| `post_hoc_failed_tagging` | 기준선 대비 `research_status_overrides.csv` 의 변경·삭제 + `forecasts/` 수정 | 태그 대상을 바꾸면 잡힌다 |

**기준선은 git 이다.** 저장소 안에 스냅샷 파일을 두면 그 파일 자체가 같이 조작될 수 있고
낡으면 거짓 안심을 준다. 커밋 이력은 그보다 지우기 어렵다.

**추가는 허용한다.** 새 예측이 생기면 원장 행도 태그도 늘어난다. 금지되는 것은
**기존 행의 변경·삭제**다 — 성적을 본 뒤 표본을 빼는 것과 구별되지 않는다.

**보류는 통과가 아니다.** git 기준선을 읽을 수 없으면 위반으로 세고 exit 1 을 낸다.

CI 배선: `.github/workflows/verify.yml` 마지막 단계. PR 에서는 `github.base_ref` 와의
merge-base 를, push 에서는 `HEAD~1` 을 기준선으로 쓴다.

## 4. 배지 문구 — 산술 충족도 '통과'가 아니다

리포트의 게이트 배지가 `{"통과" if gate["gate_p3"] else "미달"}` 이었다. 지금은 "미달"이
찍히지만 산술이 충족되는 순간 **"통과"가 렌더링된다** — 계약 `status_wording.forbidden_words`
에 등재된 단어다.

문구를 바꿨다: 미충족이면 `미달`, 충족이면 `산술 충족 · 통계적 미결 (N SE)`.
행 평균이 문턱 아래여도 SE 여유가 얇으면 통계적으로 미결이고, 그 구별이 사라지면
**배지 하나가 전체 프로그램의 지위를 잘못 말하게 된다.**

렌더된 리포트에 남은 "통과" 는 `"P3 게이트 통과 전 모든 예측은 참고 의견"` 한 곳뿐이고,
이것은 게이트가 통과되지 **않았다**는 진술이라 그대로 둔다.
