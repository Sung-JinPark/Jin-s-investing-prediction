## 1. 질문 발굴 엔진 — `src/ai_fc/question_discovery.py`

### 이식하려는 것

원장에서 earnings 는 Brier **0.02817**(3행/2문항), macro 는 0.19450, market-daily 는 0.27080 이다.
earnings 가 잘 나온 이유는 실적을 잘 맞혀서가 아니라 **질문의 구조** 때문이다.

| 성질 | 게이트에 유리한 이유 |
|---|---|
| 발행자 예보 존재 | 피예측 대상이 스스로 중심추정을 공표한다 — σ 와 z 를 세울 수 있다 |
| 임계 원거리 | 중심에서 멀면 정직 확률이 0/1 로 밀리고 `p(1−p)` 가 내려간다 |
| 비개정 판정 | 최초 공시치 판정이면 사후 개정이 결과를 뒤집지 못한다 |

엔진은 `data/calendar/events.csv` 에서 **발행자 예보가 있는 종류만** 후보화한다
(`earnings`·`fomc`·`cpi`·`nfp`·`gdp`). `other` 는 σ 를 세울 수 없어 후보가 아니다.
각 후보에 발행자 예보의 정체 · 비개정 근거 · T03 σ 경로/양 힌트 · 같은 마감의 기등록 충돌을 붙인다.

### 엔진은 임계를 정하지 않는다

**후보를 내는 쪽이 임계도 정하면 z 규율은 자기충족이 된다.** `Candidate.threshold` 는 항상 `None`
이고, 성질 카운트도 **최대 2/3** 이다 — 임계 원거리는 사람이 임계를 넣은 뒤에만 판정되므로
엔진이 스스로 3/3 을 주장하지 않는다. 원장도 읽지 않는다(성적을 보고 후보를 고르면 선택 편향).

`evaluate()` 는 임계·중심·σ·정직확률을 **전부 인자로** 받아 계약 밴드에 비춘다.
테스트가 같은 사건에서 임계만 옮겨 결과가 갈리는 것을 고정한다:
NFP 임계 −75K(중심 +70K, σ 95K) → z 1.526 **채택**, 임계 100K(중심 +55K) → **사구간 거부**.

### σ 의미론 약점을 힌트에 박아뒀다

`fomc` 의 σ 힌트에 "**위원 이견 SD 를 예측오차 SD 로 쓰는 의미론 약점**을 함께 기재",
`gdp` 에 "**중심도 GDPNow 를 써야** σ 와 출처가 일치한다", `cpi` 에 "**지평이 질문의 월과 맞는지**
반드시 확인" — 전부 `SELECTION.md` 가 거부 8건에서 실제로 잡아낸 실패 유형이다.
힌트가 실패를 미리 말해주지 않으면 같은 실패가 반복된다.

## 2. 사구간 감시 — `src/ai_fc/dead_zone_watch.py`

계약 `dead_zone.band` `[0.235, 0.765]` 과 `z_rule.bands.reject` `z < 0.7` 을 계약에서 읽는다.
둘은 같은 말의 다른 표현이다 — `Φ(−0.7) = 0.242` 가 사구간 경계다.

### 두 지점의 힘이 다르다

| 지점 | 조치 | 이유 |
|---|---|---|
| **등록 시점** | **차단** | 여기서만 정직하게 개입할 수 있다 |
| **예측 시점** | **경고만** | 예측을 사구간 밖으로 미는 것은 **극단화**이고 8-8 이 금지한다 |

예측 시점 경고에는 반드시 `NO_EXTREMIZATION` 문장이 붙는다 —
"확률을 사구간 밖으로 밀지 마라 … 올바른 반응은 **다음 질문의 임계를 다시 두는 것**이다".
이 구별이 흐려지면 감시기가 극단화 유도 장치가 된다. 테스트가 두 stage 의 `blocking` 차이와
경고 문구를 고정한다.

### 실측 — 경고 0건, 그러나 커버리지 25/61

정직 확률이 기록된 활성 25문항 중 **사구간 진입 0건**이다(최저 0.04, 최고 0.85, 그다음이 0.22).
등록 필터가 실제로 작동해 왔다는 뜻이다.

**그런데 나머지 36문항은 정직 확률이 없어 판정 자체가 불가능하다.** 그래서 감시 출력은
커버리지를 항상 함께 낸다 — 경고 0건은 "사구간 문항이 없다"가 아니라
**"볼 수 있는 것 중에 없다"** 다. 기등록 질문에는 소급하지 않는다(표시일 뿐 void·재분류·
확률 조정으로 가지 않는다).

`PROMPT_VERSION` 을 `reasoning_core_v1_1` 로 전환했다. **가중 학습이 아니라 프롬프트 절차

## 4. 게이트 이후 로드맵 — 문서만, 코드 금지

지금 쓰면 안 되는 것을 **지금 설계해 두는** 이유는, 게이트를 통과한 직후가 가장 서두르기 쉬운
시점이기 때문이다. 그때 설계를 시작하면 "표본이 충분하니 이제 뭐든 해도 된다"로 미끄러진다.

### 해소 100+ — 캘리브레이션 보정 (isotonic / Platt)

| 항목 | 사전 결정 |
|---|---|
| 발동 조건 | `v_brier_primary` 기준 **해소 100문항 이상**. 행이 아니라 **문항** 수다 |
| 적합 방식 | **cross-fit** — 같은 표본으로 적합·평가하면 보정이 성적을 만들어낸다 |
| 평가 | 보정 전/후 Brier 를 **문항 클러스터 부트스트랩**으로 비교. 한 방향이라도 유의 열위면 raw 유지(V13 의 fallback 규약 승계) |
| 배치 범위 | **파생 표시층 한정.** 게이트 판정(`v_gate_status`)은 raw rN 으로만 한다 |
| 금지 | 보정된 확률을 원장 `probability` 열에 쓰는 것. 원장은 rN 원본이다 |

### 해소 200+ — 앙상블 가중 결합

| 항목 | 사전 결정 |
|---|---|
| 발동 조건 | 해소 **200문항 이상** |
| 결합 대상 | LLM rN · ML 앙상블(`src/ai_fc/ml` 추론 전용) · 시장내재 |
| 가중 산출 | 학습 가중은 **out-of-sample 로만**. in-sample 가중은 결합이 아니라 과적합이다 |
| 배치 범위 | 표시층 → 그다음 시그널. **P3 게이트와 별개 결정**이며 자금 경로는 사용자 승인 후에만 |
| 금지 | 가중을 성적이 좋은 쪽으로 손으로 미는 것. 규칙은 결과 전에 커밋한다 |

### 지금 코드로 만들지 않는 이유

`v13` 트랙에서 PAV(isotonic)를 **적합했는데 배치는 0** 이었던 사례가 있다(V13-D10).
"적합이 없었다"와 "적합은 있었고 배치만 없었다"는 다른 진술이고, 코드가 있으면 언젠가 돈다.
100+ 전에는 코드를 두지 않는다.

## 6. 연간 계획 — 2027-01 목표와 그 산술

### 문항 수

| 항목 | 수 |
|---|---|
| 현재 해소 문항 | 7 |
| 활성 문항 | 61 |
| 그중 미예측 | 31 (T05 캘린더로 11주에 소진) |
| 마감 ≤ 2027-01-31 인 활성 문항 | 대부분 — T05 캘린더 W1~W9 |
| 계약 기대 생존율 | 85.1% (void 14.9%) |

**50문항 도달은 소화 속도가 아니라 마감 분포가 정한다.** 예측을 다 넣어도 마감이 와야 해소된다.
T05 캘린더의 마감은 2026-10-02 ~ 2027-06-30 에 걸쳐 있고, **2027-01-31 까지 마감되는 문항**이
50 도달의 상한이다. 기대 생존 85.1% 를 곱한 값이 현실적 목표치다.

### 두 단위 목표를 함께 건다

| 단위 | 현재 | 2027-01 목표 |
|---|---|---|
| 행 평균 (게이트 **정본**) | 0.15986 | < 0.18 유지 |
| 문항 등가중 (게이밍 감시) | 0.22079 | **< 0.18 로 하강** |

문항 등가중을 목표에 **병기**하는 이유: 행 평균만 보면 쉬운 질문을 여러 회차 재예측해
내릴 수 있다(T01 이 노출한 표면 — 현재 복수 회차가 primary 행의 50%). 정본은 행 평균이지만
두 단위가 **같이** 내려가야 그 하강이 실력이다.

### 회차 규율

신규 12건은 전부 `r1 + D-3` 로 등록했다 — 문항당 2회차다. 회차를 늘려 행 평균을 내리는 것은
게이트 문항 수에 기여하지 않으므로, 회차 수는 **정보가 늘어나는 시점에만** 늘린다(D-3 은
컨센서스가 형성된 뒤다). T01 패널이 문항당 회차 분포를 상시 인쇄해 이 규율을 감시한다.

### 이 계획이 틀릴 수 있는 지점

- **처리량이 아니라 마감이 병목이다.** 주 3건을 다 돌려도 2027-01 까지 마감이 오지 않는 문항은
  분모에 못 들어간다.
- **월 sub-cap 여유가 얇다** (T05: $22.36 / $25). 단가가 설계서 목표 $2.5~4 로 실현되면

- **예약 손실 2건**이 걸려 있다(T04: NFP 2건 둘 다 NO 면 행 평균 0.15986 → 0.20582).
