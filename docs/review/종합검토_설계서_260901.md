## 0. 총평 — 세 트랙 모두 규율 통과, 조정은 소수·경미

세 패키지는 **독립적으로 견고**하며 하드 게이트 위반 0건이다. 실측 재현 결과:
- **P1 라이브 카드**: 4개 지평 분위수 전부 단조, 지수 사상(anchor×e^q) 카드값과 **완전 일치**
  (h63 p50 27,583 / h21 26,912 재현 성공), 게이트 sealed∧operational 동시성 확인.
- **P1 shadow 원장**: h1/h5 해소값·CRPS·coverage 플래그가 보고서 §8과 **정확히 일치**
  (h1 −0.32%·h5 −2.07%, 방향 오류·CRPS 근소 열위를 정직하게 기록).
- **P2 통계**: before/after JSON 고아 키 0, 로그-선형 전환으로 가계 주식 이탈 +41%→−5% 반전은
  **실제 통계 오류를 잡은 정당한 수정**, 회사채 GDP% 전환의 순발행 방향 반전(닷컴 3.6%>현재 1.5%)도 옳음.
- **P3 컴플라이언스**: "받아진다 ≠ 써도 된다" 판정 기준, 영수증-전송 불일치(#107) 자가 발견,
  봉인 해시 우회를 신규 비봉인 모듈로 처리(#116 §4.1)한 것 모두 모범적.

아래는 **조정·확인이 필요한 소수 항목**이다. 심각도: 치명 0 / 중대 0 / 경미·확인 7.

## 1. 조정 권고 (경미·확인)

### C-1 [경미·표기] 라이브 카드 h63 "+4.5%"는 +4.4%가 정확
- **증거**: p50 로그수익 0.04374 → e^0.04374−1 = **+4.471%**. 반올림 시 +4.5%로 보이나
  보고서 자신의 검산은 "26,402.42 × e^0.0437 = 27,583"으로 지수 레벨은 정확. 백분율 표기만
  경계 반올림(4.47%)에서 +4.5로 올림됨. h21은 +1.9%로 정확(1.93%).
- **조정**: 라이브 카드·보고서 §7의 h63 수익률을 +4.5% → **+4.47%** 또는 **+4.4%**로 통일.
  지수 레벨(27,583)·분위수는 무변경. 사소하나 "참고 의견" 카드의 유일한 수치 표기 불일치.

### C-2 [확인] shadow 예측 원장의 origin_date 필드 결측
- **증거**: `shadow_forecasts.main.jsonl` 2행 모두 `origin_date=None`으로 파싱됨(horizons·model_id는 정상).
  보고서는 origin 2026-08-14·2026-08-28을 명시하는데 원장 최상위 키에는 날짜가 없음 —
  다른 키(anchor_date 등)에 있거나, 직렬화 시 필드명 불일치 가능.
- **조정**: 원장 스키마에서 origin 식별 필드명을 확인. 라이브 카드가 "2026-08-28 종가 기준"을
  올바르게 표시하므로 실제 데이터는 존재하나, **원장 최상위 origin_date 명시**가 감사 추적에
  유리(포워드 표본 성숙 판정이 이 필드에 의존).

### C-3 [확인] 미이전 fredgraph 잔여의 경계 명문화
- **증거**: P3 §4.2 + P1 §4.1이 timeseries v4/v5/v6 PIT 수집기의 fredgraph 유지를
  "provenance 해시 사유"로 정당화. 그러나 P1 §4.1이 밝혔듯 **fredgraph 스크랩은 ~10일 지연**이
  실측됨. v4/v5/v6가 신선도 게이트를 갖는다면 동일 기아가 잠복.
- **조정**: v4/v5/v6가 (a) 신선도 게이트를 갖지 않는 과거-only 수집기인지 (b) 아니면 V2와 동일한
  official_api_transport 패턴이 필요한지 **1줄 판정**을 KNOWN_LIMITS에 명시. 지금은 "별도 설계
  필요 시 착수"로만 남아 경계가 모호.

### C-4 [확인] cross_asset 첫 FRED 스냅샷 no-op의 자동 검증
- **증거**: P3 §9 "FRED의 08-31 종가 발행 대기 — 자동(정기 실행), 확인만". no-op이 결함이
  아님은 맞으나, **첫 실전 실행이 잠복 버그를 드러낸 전례**(#113 예외 삼킴 가드)가 바로 이 경로에 있었음.
- **조정**: 첫 FRED cross_asset 스냅샷이 실제로 생성될 때 #113 회귀 테스트 2건이 커버하는지
  확인하고, 생성 성공을 P3 미해결 표에서 명시 종료. (자동이라도 첫 실행은 관찰 대상.)

### C-5 [경미·일관성] P2 valuation_proxy 배율 정의 전환의 시계열 연속성
- **증거**: valuation_proxy가 (전) 19.2배[CPATAX 분모] → (후) 29.8배[비금융 세후이익 분모]로
  **분모 교체로 절대수준이 크게 이동**. 통계적으로 옳은 수정이나, 라이브 차트를 시계열로 보는
  사용자에게는 배율이 하루 만에 19→30으로 점프한 것으로 보임.
- **조정**: 차트 caveat에 "2026-09-01 분모 정의 변경(전체 경제→비금융)으로 이전 배율과 수준
  비교 불가"를 **1줄 추가**. 부록 B의 정의 설명은 있으나 "과거 값과의 단절" 명시가 없음.
  (P2가 이미 정의 caveat는 넣었으므로 연속성 단절 한 줄만 보강.)

### C-6 [확인] household_balance_sheet 소표본의 신뢰구간 미표기
- **증거**: 로그-선형 전환으로 채권 이탈 +18%가 나오는데 부록 B가 "연간 11개 관측 소표본"을
  자인. 11점 OLS 추세의 외삽 이탈률은 신뢰구간이 넓음. 현재 점추정만 표시.
- **조정**: 소표본 항목(채권)에 점추정만 유지하되 caveat를 "11점 회귀라 이탈률 불확실성 큼"으로
  구체화(현재 "소표본"만). 수치 재계산 불요 — 표기 강화만.

### C-7 [정리] DECISIONS 순서 뒤틀림 + 병렬 세션 method_changes 번호
- **증거**: P3 §9 "12-8·12-9가 파일상 12-7 앞에 위치(삽입 앵커 부작용, 내용 무결)". P1은
  method_changes r19·r20 신설, P2는 병렬 세션이 별도 번호 사용.
- **조정**: 내용 무결이므로 선택적. 다만 **번호=시간순 불변식**을 KNOWN_LIMITS나 CLAUDE.md에
  명문화하면 병렬 세션 체제에서 재발 방지. (기록 자체는 정확하니 우선순위 낮음.)
