# 추세선 차트 워크스페이스와 자산 확장 (2026-10-21)

상·하방 추세선 화면의 차트를 누르면 전체 화면 워크스페이스가 열린다. 그리는 일은 모두 이 화면에서
하고, 페이지의 차트는 미리보기(저장된 내 선 포함)로 남는다. 자산은 6종에서 10종으로 늘었다.
모든 선은 참고선이며 매매 신호나 확률이 아니다.

엔비디아·마이크론 각 1,080봉(2026-10-21 기준). 전체·핵심·대표·장기 경계 4개 층 모두 ready.

### 등록 경계

- 공개 투영(`data/trendlines/latest.json`)은 네 자산의 HOLD 스냅샷을 원장에 **추가**만 했다. 공개 사이트에는 가격이 없다.
- `trendlines-verify`는 새로 등록된 자산이 첫 HOLD 발행을 기다리는 것은 허용하되, 스냅샷 이력이 있는 자산이
  포인터에서 빠지는 것은 계속 거부한다.
- 로컬 갱신기의 사본 레지스트리는 **자산 추가만** 받는다. 이미 수집한 자산의 정의가 다르면 갱신을 멈춘다.
- 브라우저는 이전 버전 갱신기(7행 상태)도 받아들이고, 선택한 자산이 없으면 갱신기 업데이트를 안내한다.
  이전 6자산 백업 파일도 그대로 가져온다.

## 3. 저장 규약 (변경 없음)

- 새 도구는 모두 기존 v2 두-기준점 레코드다. 수평선은 같은 가격의 이웃 두 거래일, 채널은 생성 축(선형·로그)에서
  셋째 점을 지나는 평행선 하나를 더 저장한다. 연장값과 이름만 다르다. 저장 스키마·백업 계약은 그대로다.
- 측정은 화면에만 있고 저장·원장·자동선에 들어가지 않는다.
- 워크스페이스의 확대 구간과 가격축 수동 범위는 저장하지 않는다(페이지 차트의 보기 상태도 건드리지 않는다).
- 닫을 때 미저장 편집이 있으면 저장 여부를 묻는다. 임시본은 브라우저에 남는다.

## 4. 알려진 한계

- 로컬 갱신기는 자산마다 저장소 전체 원본·영수증·아카이브를 매 검수 단계에서 다시 해시한다. 같은 작업자 안에서
  바이트가 같은 아카이브는 다시 디코딩하지 않는다(2026-10-22 복사본 실측: 자산당 1회 갱신 392초 → 51초, 재시작 직후
  첫 갱신 1,251초 → 295초. 상세: `docs/TRENDLINES_PRIVATE_RESEARCH.md`). 해시 비용은 여전히 저장량에 비례해 늘고,
  재시작 직후 첫 주기는 모든 아카이브를 한 번씩 다시 검수한다.
- 공개 사이트에서 차트를 열면 기존처럼 이 PC의 로컬 화면(127.0.0.1:8878)으로 이동한다.
- **2026-10-22 17:04 KST 마이크론 갱신 `MemoryError` — 원인 판정(2026-10-23, 사본 측정)**. 다섯 검수기
  (research·full·critical·representative·long_boundaries)의 `verify`가 스냅샷마다 디코딩한 본문 전체를 개정 색인
  (`snapshots[sid] = archive`)에 붙들어, 검수 한 번의 상주 메모리가 **저장소 크기에 비례**했다. 수집 창 10년 이동(§5)
  으로 수집본당 크기가 2.2배가 되자 한계를 넘었다. 복사본(연구 스냅샷 207개 445MB)에서 `research.verify` 1회 실측:
  PR #330 이전 코드 최고 RSS 1,232MB·private 1,659MB·종료 후 765MB 잔류 → #330 코드 최고 RSS 127MB, 3회 반복해도
  112→116MB로 평탄. 수정은 **PR #330(2026-10-22 17:41 머지, 17:44 재설치)** 이 이미 반영했다 — 검수기는 본문 검증을 끝낸
  뒤 식별 필드만 남긴다. 검증 패스·불변성·보장은 바뀌지 않았다. `VerifiedReplayCache`는 키(해시 튜플)와 검증 함수
  참조만 담고 디코딩 결과를 붙들지 않는다(항목 수 = 저장소 스냅샷 수, 207개). 재발 시 확인 순서: ① 설치본
  `app/src/ai_fc/trendlines/*.py` 가 main 과 같은지, ② 이 PC의 커밋 한도(RAM 32GB + 페이지파일 19GB)를 다른 프로세스가
  채우고 있는지 — 측정 시점 사용 중 43GB. 남은 비용 한계: 검수는 여전히 매 호출마다 저장소 전체 스냅샷을 읽고
  디코딩하며(자산당 첫 검수 콜드 1,119초, 캐시 적중 후 23~26초), 이는 메모리가 아니라 시간 문제다.

## 5. 수집 기간과 초기 표시 구간 (2026-10-22)

- 수집 창은 고정 시작일(2022-07-01)이 아니라 **이동 창**이다: 거래소 자산 10년(≈2,520봉), 비트코인 6년(≈2,192봉).
  `tools/refresh_private_trendlines.py`의 `capture_window`가 매 수집 때 오늘 기준으로 계산하고, 가장 오래된 날은
  새 날이 쌓이는 만큼 빠진다. 전체 기하의 상한 `MAX_BARS`(4,096)에 잘림 없이 머문다.
- 더 길게 잡지 않은 근거 두 가지(실측): ① Yahoo의 KRX 이력에는 2015-08-14(임시 휴장일) 행이 들어 있어 달력 게이트가
  **수집 전체**를 거부한다(코스피·삼성전자·SK하이닉스 15년 창에서 재현). ② 전체 기하 재검산은 피벗 쌍 전수라 봉 수의
  제곱 이상으로 는다 — 1,047봉 10.8초 → 2,520봉 57.7초 → 3,800봉 325초(SK하이닉스 스냅샷 기준), 비트코인은 2,920봉 204초·2,192봉 110초.
  저장량도 수집본당 약 2.2배가 된다.
- 페이지 차트의 `최근 4년`(이전 '전체 기간') 범위는 거래소 1,008봉·비트코인 1,461봉만 그린다. 워크스페이스는 그 구간으로
  열리고, 휠 축소·`−`·`전체` 프리셋으로 수집된 전체 봉까지 넓어진다. 내 선은 날짜·가격으로 저장되므로 창이 이동해도
  좌표가 바뀌지 않는다.
- 반영 절차: 머지 뒤 `powershell -NoProfile -File tools/install_private_trendlines.ps1`로 갱신기를 재설치해야 새 창으로
  수집한다. 첫 주기는 자산마다 10년치를 새로 받아 재검산하므로 평소보다 오래 걸린다.

### 추가 기능

- 봉 주기 1D·1W·1M, 차트 종류 캔들·바·라인·영역·하이킨아시. 주·월봉은 일봉에서 브라우저가 합친다.
- 주·월봉에서는 확대 한계(최소 5봉)·방향키 1봉 이동·십자선·자석·프리셋 하한이 그 주기의 봉을 기준으로 움직인다. 주기를 바꾸면 봉 간격과 오른쪽 끝을 유지해 범위가 넓어진다. 선 기준점은 항상 일 단위 날짜로 저장한다.
- 지표: MA 20·50·200, EMA 20, 볼린저 20·2, 거래량, RSI 14, MACD 12·26·9. 표시 전용이며 원천·자동선·원장에 들어가지 않는다.
- % 가격축(화면 첫 봉 대비), 최신 봉으로 돌아가는 ≫ 단추, 월·연 경계 시간축.
- 그리기 도구: 수직선, 사각형, 피보나치 되돌림, 화살표, 텍스트. 자산별 선 한도 20→100개.
- 미래 날짜에도 기준점을 찍는다. 달력은 평일(가상자산은 매일) 1,500일 연장이고, 찍은 날이 나중에 휴장으로 밝혀지면 다음 거래일에 놓인다.

### 저장 규약 변경

레코드는 여전히 두 기준점이다. 선택 키 `shape`(`rect`·`fib`·`vertical`·`text`)만 추가했고 없는 옛 레코드는 그대로 유효하다.
수직선·텍스트의 둘째 기준점은 이웃 거래일이다. 새 도구로 그린 선이 든 백업은 이전 코드에서 가져올 수 없다.

### 종목 검색

- 자산 메뉴 맨 위 입력창에 티커·회사명·한글을 넣으면 고른 종목이 바로 차트로 열린다. 최근 검색 8개를 기억한다.
- 경로: 브라우저 → 로컬 갱신기 `/api/private-trendlines/symbol-search|symbol-bars/<base64url>` → `trendlines/symbol_lookup.py` →
  Yahoo 검색·일봉 차트(`query1.finance.yahoo.com`), 한글은 Naver 자동완성(`ac.stock.naver.com`). 호스트는 코드에 고정이고 기호는 정규식을 통과해야 URL에 들어간다.
- 시세는 프로세스 메모리 캐시(검색 10분·일봉 15분)에만 있고 저장소·원장·공개 투영에 쓰지 않는다. 공개 사이트는 여전히 시세를 싣지 않는다.
- 끝나지 않은 세션은 봉이 아니라 '장중' 관측점으로만 표시한다. OHLC가 깨진 행은 고치지 않고 버린 뒤 `dropped_rows`로 센다.
- 내 선은 자산 ID `sym:<기호>`로 같은 IndexedDB에 저장되고 백업에 포함된다.
- 검색 종목에는 **자동 추세선이 없다.** 자동선은 검증된 스냅샷에서만 나온다(전체 기하 재검산 O(P²)). 고정 자산 10종만 자동선을 유지한다.
- 코드 반영은 갱신기 재설치가 필요하다(`tools/install_private_trendlines.ps1`).

### 넣지 않은 것

분봉(원천이 일봉뿐), 가격 알림, 다중 차트 배치, 비교 종목 겹치기, 사용자 지표 스크립트, 바 리플레이, 가격축 반전. TradingView의 도구·지표 전량이 아니라 위 목록까지다.
