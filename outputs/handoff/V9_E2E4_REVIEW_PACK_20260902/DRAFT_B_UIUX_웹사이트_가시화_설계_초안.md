# [초안 B] 웹사이트 UI/UX 가시화 설계 — 직관적 이해를 위한 개선안

> 지위: **초안**. 받은 Claude가 이 초안을 그대로 따를 필요 없음 — 저장소 실측 후 더
> 고도화된 설계로 대체 가능. 단, §0의 불변 제약은 어떤 설계에서도 유지되어야 한다.
> 작성: 2026-09-02, 라이브 사이트(https://sung-jinpark.github.io/Jin-s-investing-prediction/)
> 와 dashboard.js 실코드 기준.

## 0. 불변 제약 (설계 자유도의 경계)

- **fail-closed 표시 규약**: 게이트 미통과 수치는 서버 단계에서 제거된다. UI는 "숨겨진
  숫자를 예쁘게"가 아니라 "왜 안 보이는지"를 설명해야 한다.
- **참고 의견 지위**: 모든 예측 표면에 참고 의견 배지·매매 신호 아님 고지 유지 (CLAUDE.md).
- **확률 표기**: 1% 단위, 80% 신뢰구간 병기 원칙. "약 20~25%" 금지.
- 판정 문구("과열/버블") 렌더 금지, 확률공간 결합 표현 금지.
- 기술 스택: 정적 GitHub Pages + 단일 dashboard.js(프레임워크 없음) — 무거운 차트
  라이브러리 도입은 번들 예산(ADR-002 임베드 용량)과 상충. SVG 인라인 렌더 관행 유지.

## 1. 진단 — 현재 사이트에서 이해가 어려운 지점

1. **시계열 카드가 숫자 나열이다**: 4개 호라이즌 카드(중앙 지수·수익률·대역·상승확률)는
   정확하지만 "분포"가 그림으로 보이지 않는다. path 탭은 v8에서 비활성.
2. **게이트 상태가 텍스트다**: "봉인 게이트와 운영 신선도 게이트를 모두 통과한 동안에만…"
   — 어떤 게이트가 무엇이고 지금 어떤 상태인지 시각 요소가 없다.
3. **통계 27개 차트가 평면 나열**: 카테고리(valuation/credit/liquidity…)는 있지만 "지금
   닷컴 대비 어디가 뜨거운가"의 한눈 요약이 없다.
4. **용어 장벽**: CRPS·p10–p90·coverage·PIT 같은 용어가 설명 없이 노출된다.
5. **모바일에서 카드 밀도 과다** (구현 시 실측 필요).

## 2. 제안 A — 시계열 페이지: "분포를 그림으로"

### A-1. 부채꼴 밴드 차트 (fan chart) — path 탭 활성화
- 데이터는 이미 있다: latest 포인터의 horizons {1,5,21,63}별 p10/p25/p50/p75/p90 지수
  레벨 + anchor. 4개 지점을 세션 축(0·1·5·21·63)에 놓고 밴드 2겹(p10–p90 연한 톤,
  p25–p75 진한 톤)과 중앙선(p50)을 SVG로 그린다. 최근 63세션 실적선을 앞에 붙여
  "과거 1/4 · 전망 3/4" 구도(기존 v2 path 패널 관행)를 재사용.
- 밴드 위에 상승확률을 호라이즌별 마커로 병기 (예: 63d 지점에 "▲72%").
- 구현: 기존 `timeseriesPathSvg` 스타일 함수를 v8 스키마용으로 신설(기존 함수 무수정).
  보간은 선형이면 충분 — "곡선 미학"보다 "이건 구간 추정"이라는 정직성이 중요.

### A-2. 게이트 상태 위젯
- 카드 상단에 2칸 게이트 배지: `봉인 평가 PASS`(고정, run id 툴팁) ·
  `운영 신선도 OK`(freshness 그룹 5종의 최악 age를 툴팁으로). HOLD 시 이 위젯이
  이유(예: "NASDAQCOM 관측 52h > 48h 한도")를 그대로 보여준다 — 데이터는 latest
  포인터의 gate.reasons·operational.freshness에 이미 있다.
- 효과: "왜 숫자가 사라졌지?"가 버그가 아니라 설계임을 사용자가 즉시 이해.

### A-3. 용어 즉석 설명
- p10–p90·상승확률·CRPS 개선에 `<abbr>` 또는 탭-툴팁 1줄 설명. 예: "p10–p90:
  100번 중 80번은 이 범위 안에 들도록 설계된 구간". 별도 용어집 페이지보다 즉석이 낫다.

## 3. 제안 B — 통계 페이지: "한눈 요약 → 상세"

### B-1. 히트 스트립 (카테고리 온도계)
- 최상단에 카테고리별 1행 스트립: 각 차트의 "닷컴 대비 현재 위치"를 3단(아래/유사/위)
  아이콘으로 압축, 클릭 시 해당 차트로 스크롤. 기존 approach-alert 경계 데이터(접근 경보
  단계)가 이미 데이터 파생으로 존재하므로 그 등급을 재사용 — 새 판정 로직 금지.
- 반드시 caveat 동반: "위치 비교는 참고 지표이며 신호가 아님".

### B-2. 차트 카드 정보 위계 재정렬
- 현재: 제목→차트→결론→caveat. 제안: 제목 옆에 **한 줄 결론 선행**(지금도 conclusion
  필드 존재), caveat는 접힘 기본 + "주의 N건" 배지로 존재감 유지. 접힘은 사용자
  액션이므로 공시 후퇴가 아니라는 원칙 검토 필요 — 대안: caveat 첫 문장은 항상 노출.

### B-3. 두 시대 비교의 시각 문법 통일
- 닷컴=빨강 계열, 현재=초록/청록 계열이 이미 관행 — 전 차트에서 강제 통일하고
  범례를 카드 밖 전역 1회로 승격 (반복 제거).

## 4. 제안 C — 전역

- C-1. **오늘 페이지에 "시스템 상태" 3칸**: 예측 원장 N건·해소 N건·다음 재예측 예정 —
  기록과 검증 페이지 데이터의 요약 재사용.
- C-2. **로딩·빈 상태 정직화**: statistics.json 지연 로드 중 스켈레톤, 실패 시
  "데이터를 불러오지 못했습니다(캐시 아님)" — 조용한 빈 화면 금지.
- C-3. 모바일: 카드 grid 1열 강제 구간 실측 후 breakpoints 조정.

## 5. 구현 순서 제안 (작은 PR 여러 개)

1. A-2 게이트 위젯 (데이터 이미 있음, JS만) → 2. A-1 fan chart → 3. A-3 용어 툴팁
→ 4. B-2 위계 → 5. B-1 히트 스트립 → 6. C 전역. 각 단계마다 스크린샷 검증
(대시보드 브라우저 검증 함정 메모리 참조: hidden 패널 rAF 멈춤 주의).
