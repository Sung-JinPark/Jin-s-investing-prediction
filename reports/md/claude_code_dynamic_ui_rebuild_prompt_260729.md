# Claude Code 작업지시 — 리컬러링이 아닌 동적 UI 전면 재구축

## 먼저 이해할 것

직전 결과물은 실패로 판단한다.

실패 이유는 기존 대시보드의 작은 카드·표·정적인 문서 레이아웃을 유지한 채 색상과 폰트만 바꿨기 때문이다. 이번 작업의 목표는 “비슷한 색”이 아니다. **Codex 사이트처럼 큰 타이포그래피, 큰 수치, 넓은 차트, 화면별로 달라지는 레이아웃, 실제로 반응하는 인터랙션을 가진 현대적인 데이터 프로덕트로 구조 자체를 다시 만드는 것**이다.

색상 변경은 전체 작업의 10% 이하로 취급한다. 레이아웃, 크기 체계, 정보 우선순위, 상호작용이 바뀌지 않았다면 완료가 아니다.

계획만 보고하지 말고 구현, 실행, 브라우저 검증까지 끝내라.

## 기준 사이트

시각적·상호작용 기준은 아래 로컬 Codex 구현이다.

- `codex-forecast-demo/app/page.tsx`
- `codex-forecast-demo/app/globals.css`
- 배포본: `https://codex-nasdaq-outlook-260728.jovial-frog-4374.chatgpt.site`

기준 사이트에서 반드시 직접 확인할 요소:

1. 첫 화면의 큰 헤드라인과 비대칭 Hero 구성
2. 화면 폭을 크게 사용하는 핵심 확률 카드 3개
3. 상단 시장 스냅샷 스트립
4. 6개 화면을 실제로 전환하는 내비게이션
5. 높이 430px 이상의 주간 시나리오 차트와 혁신 사이클 차트
6. 기간 프리셋, 검색, 필터, 질문 상세, 라운드 선택, as-of 조회의 실제 동작
7. 어두운 분석 패널과 밝은 편집형 섹션이 교차하는 화면 리듬
8. 작은 카드만 반복하지 않고 섹션마다 서로 다른 크기와 구성을 사용하는 방식

기준 사이트의 문구나 데이터를 복사하지 말고, **레이아웃 원리와 상호작용 밀도만 대상 대시보드에 적용**한다.

## 절대 보존할 것

다음 항목은 UI 개편과 분리하여 그대로 유지한다.

- 기존 질문, 예측값, 라운드, 마감일, 해소 결과
- `SCENARIO`, forecast registry, DB 스키마와 동기화 로직
- 주간 경로 배열, 이벤트 배열, 위험도 배열, 역사적 사이클 데이터
- 해시·ID·질문 연결 관계
- tooltip, 범례, 화면 전환, 기간 조회, 필터, as-of 조회의 기존 의미
- 데이터 생성 파이프라인과 예측 계산 로직

`65%`, `52%`, `58%`는 서로 다른 등록 질문의 최신 확률이다. 합계가 100%인 시나리오 가중치가 아니다. 기존 시나리오 가중치와 혼합하거나 재해석하지 마라.

## 이번에 반드시 바꿀 것

### 1. 전체 화면 구조

기존의 “작은 카드가 균일하게 반복되는 관리도구형 대시보드” 구조를 버린다.

다음과 같이 정보 크기를 계층화한다.

- 1단계: 화면 전체를 지배하는 Hero와 56–88px급 헤드라인
- 2단계: 64–112px급 핵심 확률 숫자
- 3단계: 화면 폭을 넓게 사용하는 실차트와 분석 패널
- 4단계: 보조 지표, 필터, 표, 주석

콘텐츠를 중앙의 좁은 열에 가두지 말고 데스크톱에서 최대 1440–1540px 폭을 적극적으로 사용한다. 모든 컴포넌트를 같은 크기의 카드에 넣지 않는다. 일부 섹션은 전체 폭, 일부는 2열 비대칭, 일부는 숫자 스트립, 일부는 표 형태여야 한다.

### 2. 첫 화면

1440px 화면에서 첫 스크롤 안에 아래 요소가 한눈에 보여야 한다.

- 브랜드, LIVE/갱신 시각
- Nasdaq 현재가, ATH 대비, −10% 선, breadth, 경기 국면
- 큰 시장 판단 문장
- 현재 stance를 보여주는 별도 분석 블록
- 핵심 예측 3개를 보여주는 큼직한 숫자 카드

Hero의 제목은 단순한 페이지 제목이 아니라 시장 판단을 한 문장으로 보여줘야 한다. 제목과 수치가 화면의 시각적 중심이어야 한다.

### 3. 시장 전망 화면

이 화면은 정적 카드나 가격 맵으로 대체할 수 없다. 아래 두 그래프를 실제 SVG 또는 canvas 차트로 렌더링한다.

1. 주간 시장 시나리오
   - 상승·ATH 돌파
   - 상승·ATH 미달
   - 조정·횡보
   - 과거 유사 사이클 참조선
   - FOMC·실적·선거 등 이벤트
   - 하단 주간 위험도 스트립

2. 역사적 혁신 사이클 비교
   - AI 현재
   - 닷컴
   - 일본 1989
   - Nifty Fifty 1972
   - 크립토 2021
   - 바이오 2015
   - 다우 1929

데스크톱에서 각 차트의 실제 렌더 높이는 최소 430px로 한다. 모든 계열의 범례와 hover tooltip이 동작해야 한다. 차트가 빈 영역, 장식용 선, 정적 이미지로 보이면 실패다.

### 4. 여섯 개 화면의 동적 동작

아래 6개 화면은 같은 문서의 앵커 이동이 아니라 사용자가 눌렀을 때 내용과 레이아웃이 실제로 전환되어야 한다.

1. 요약
2. 시장 전망
3. 기간 조회
4. 예측 목록
5. 시점 조회
6. 적중 이력

전환 시 활성 탭이 명확해야 하고 180–260ms 범위의 짧은 등장 전환을 적용한다. 과도한 모션은 쓰지 않되, 눌러도 아무 변화가 없는 정적 문서처럼 보이면 안 된다.

### 5. 반드시 동작해야 할 인터랙션

- 기간 조회의 8월·9월·10월·11월·연말 프리셋
- 시작일·종료일 변경 시 차트와 기간 수익률 재계산
- 질문 목록의 텍스트 검색
- 도메인과 상태 필터
- 질문 행 선택 시 상세 화면 진입
- 질문 상세의 라운드 선택
- AI·ML·시장 확률 비교 차트
- as-of 날짜 변경 시 해당 시점까지의 최신 예측 재구성
- 적중 이력의 Brier·캘리브레이션 표시
- 차트 tooltip과 범례

버튼은 실제 state를 바꾸고, 필터는 실제 결과 개수를 바꾸며, 날짜는 실제 차트 데이터 범위를 바꿔야 한다.

### 6. 시각적 리듬

다음 원칙을 적용한다.

- 어두운 Hero/차트 패널과 밝은 분석 영역을 교차 배치
- 큰 여백과 촘촘한 데이터 영역을 번갈아 사용
- 섹션마다 같은 카드 UI를 복제하지 않음
- 직각에 가까운 편집형 패널 사용
- 작은 mono eyebrow와 큰 sans-serif 제목의 대비
- 수치는 mono 글꼴로 크게 강조
- 경계선은 얇게, 그림자는 최소화
- hover 시 배경·선·위치가 미세하게 반응
- 위험과 하락은 coral, 상승과 활성 상태는 lime/teal을 제한적으로 사용

### 7. 금지 사항

아래 중 하나라도 해당하면 다시 작업한다.

- 기존 레이아웃을 그대로 둔 채 배경색·글자색만 변경
- 모든 정보를 300px 안팎의 작은 rounded card에 넣기
- Bootstrap/Admin template처럼 동일 카드 그리드를 반복
- Hero가 없거나 제목이 일반 본문 크기
- 그래프를 KPI 카드나 가격 막대로 대체
- 버튼·탭·필터가 보이기만 하고 동작하지 않음
- 가짜 데이터나 임의의 새 확률을 추가
- 기존 그래프 계열을 삭제하거나 축약
- 장식용 SVG, stock image, 금융 아이콘으로 빈 공간을 채움
- 모바일에서 차트를 숨김
- “색상 변경 완료”를 리디자인 완료로 보고

## 구현 순서

1. 대상 대시보드의 데이터 계산 코드와 UI 렌더링 코드를 분리해 파악한다.
2. Codex 기준 사이트를 1440px과 390px에서 열어 화면 구조와 인터랙션을 확인한다.
3. 공통 shell, 시장 스트립, 화면 내비게이션, Hero부터 다시 만든다.
4. 요약 화면의 대형 확률 카드와 비대칭 분석 영역을 만든다.
5. 두 개의 핵심 차트를 실제 데이터로 연결한다.
6. 나머지 4개 화면과 필터·기간·상세·as-of 동작을 연결한다.
7. 반응형과 접근성을 정리한다.
8. 기존 테스트, 데이터 보존 검사, 브라우저 검증을 수행한다.

구현 중 기존 계산 로직을 UI 코드로 복사하거나 다시 작성하지 마라. 기존 데이터 객체를 읽어 표현 계층만 교체한다.

## 반응형 기준

- 1440px: 전체 시각 계층과 비대칭 레이아웃이 모두 표현
- 768px: 핵심 정보가 1열 또는 2열로 재배치
- 390px: 제목과 숫자는 충분히 크되 가로 넘침 없음
- 모바일 차트는 숨기지 않고 높이 320px 이상 또는 명확한 가로 스크롤 제공
- 표는 잘리거나 축소되어 읽을 수 없게 만들지 말고 가로 스크롤 허용
- `prefers-reduced-motion` 지원
- 키보드 focus와 기본 ARIA label 유지

## 합격 기준

작업 완료 전에 아래 항목을 직접 검증한다.

1. 기존 테스트와 빌드가 모두 통과한다.
2. 6개 내비게이션 화면이 모두 열린다.
3. 시장 전망 화면에 실제 크기가 0이 아닌 SVG/canvas 차트가 정확히 2개 이상 보인다.
4. 두 그래프의 모든 데이터 계열과 범례가 존재한다.
5. 기간 프리셋을 누르면 날짜와 그래프가 변한다.
6. 질문 검색 결과 수가 입력에 따라 변한다.
7. 질문 상세에서 라운드를 바꾸면 확률과 근거가 변한다.
8. as-of 날짜를 바꾸면 해당 시점의 예측만 표시된다.
9. 브라우저 콘솔 오류가 없다.
10. 1440px, 768px, 390px 스크린샷에서 레이아웃이 깨지지 않는다.
11. 기존 질문·확률·시나리오 배열·해소 데이터의 diff가 없다.
12. 첫 화면 스크린샷만 보아도 기존 버전과 레이아웃이 명확히 다르다.

특히 12번이 중요하다. 기존 버전과 새 버전의 스크린샷을 흑백으로 비교해도 크기 체계와 레이아웃 차이가 보여야 한다. 색을 제거했을 때 차이가 사라진다면 실패다.

## 완료 보고 형식

완료 보고에는 아래 내용만 명확히 포함한다.

- 구조적으로 다시 만든 영역
- 구현한 동적 인터랙션 목록
- 두 핵심 차트의 실제 렌더 크기와 계열 수
- 데이터·예측 로직 보존 확인 결과
- 테스트·빌드·브라우저 콘솔 결과
- 1440px·768px·390px 검증 결과
- 수정한 파일 목록
- 기존 화면과 새 화면의 스크린샷 경로

“Codex와 비슷한 색으로 바꿨다”는 보고는 받지 않는다. **Codex처럼 크게 읽히고, 화면이 전환되고, 데이터가 움직이는 사이트를 완성하라.**
