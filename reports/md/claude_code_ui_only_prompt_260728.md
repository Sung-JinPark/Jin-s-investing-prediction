# ClaudeCode용 UI 전용 리디자인 프롬프트

아래 작업은 **기존 Jin's Investing Prediction Solution의 기능·데이터·예측 로직을 그대로 보존한 채 UI만 리디자인하는 작업**이다.

## 목표

현재 대시보드의 모든 기능과 차트를 유지하면서, 로컬 데모 사이트의 시각 언어를 적용하라.

읽기 전용 디자인 참조:

- `codex-forecast-demo/app/page.tsx`
- `codex-forecast-demo/app/globals.css`

참조 사이트의 데이터 구조나 문구를 복사하지 말고 다음 디자인 요소만 차용한다.

- 짙은 잉크색 배경과 라임 포인트
- 매우 큰 헤드라인과 넉넉한 여백
- 얇은 경계선 기반 카드
- 숫자를 크게 강조하는 확률 카드
- 어두운 Hero 영역과 밝은 분석 영역의 대비
- 모노스페이스 라벨, 작은 대문자 eyebrow, 절제된 코랄 위험색
- 과도한 그림자·둥근 카드·장식 아이콘을 피하는 편집 디자인

## 절대 변경 금지

UI 전용 변경이다. 아래 항목은 수정하지 마라.

1. 예측 확률, 질문, 임계값, 기준일, 시나리오 데이터
2. `SCENARIO`, forecast registry, DB 스키마, 동기화·예측·캘리브레이션 로직
3. 기존 그래프가 사용하는 주간 경로 배열, 유사 사이클 배열, 이벤트 일정
4. 차트 tooltip, legend, 축, 이벤트 표식, 탭 전환과 기간 조회 동작
5. 요약·시장 전망·기간 조회·예측 목록·시점 조회·적중 이력의 6개 화면
6. 예측 원장과 `.hashes`

`65%`, `52%`, `58%`는 서로 다른 등록 질문의 최신 확률이다. 이를 합계 100%의 연말 시나리오 가중치로 임의 변환하거나 하드코딩하지 마라. 시나리오 가중치는 기존 정본에서만 읽어라.

## 그래프 보존 요구사항

현재 “시장 전망” 화면에 있는 다음 두 그래프를 반드시 유지한다.

1. **연말 시장 전망 시나리오 그래프**
   - 상승·ATH 돌파
   - 상승·ATH 미달
   - 조정·횡보
   - 과거 유사 사이클 참조선
   - FOMC·실적·선거 등 상단 이벤트 표식
   - 하단 주간 변동성 위험 표시

2. **과거 혁신 사이클 비교 그래프**
   - AI 현재
   - 닷컴 1996
   - 일본 1989
   - 니프티50 1972
   - 크립토 2021
   - 바이오 2015
   - 다우 1929

차트 라이브러리와 데이터 바인딩은 유지하고 표현만 다음처럼 바꾼다.

- 차트 패널 배경: `#ffffff`
- 페이지 배경: `#f3f6f0`
- 기본 텍스트: `#07110f`
- 상승 강조: `#4f7f26` 또는 기존 파랑
- 핵심 전망선: `#2563d9`
- 하락·위험선: `#ff8066`
- 현재 AI 비교선: 굵기 3px, 다른 과거선은 낮은 채도·1px
- grid line은 낮은 대비로 단순화
- 범례·축·이벤트 라벨의 가독성을 유지
- 데스크톱에서 그래프 높이 최소 460px
- 모바일에서는 가로 스크롤 또는 축약 레이아웃을 제공하되 선을 숨기지 않음

## 화면별 방향

### 공통 상단

- 어두운 Hero/header를 사용한다.
- 브랜드, P1 상태, LIVE, 갱신 시각을 한 줄에 배치한다.
- Nasdaq 현재가, ATH, −10% 조정선, 시장 폭, 경기 국면을 얇은 경계선 카드로 표시한다.
- 기존 값은 코드에서 읽으며 문구나 숫자를 복제하지 않는다.

### 요약

- 첫 화면에서 현재 시장 판단과 핵심 수치를 큰 타이포그래피로 보여준다.
- 확률 카드는 데모의 `forecast-card` 시각 언어를 적용한다.
- 다가오는 일정과 검증 진행률은 기존 데이터를 유지한 채 밝은 분석 영역에 배치한다.

### 시장 전망

- 두 그래프가 첫 스크롤 안에서 명확히 보이도록 우선순위를 높인다.
- 그래프를 Price Map이나 정적 카드로 대체하지 않는다.
- 제목·설명·범례·차트·주석의 계층을 분명히 한다.

### 나머지 화면

- 기존 필터, 테이블, 상세 추론, as-of 조회 기능을 유지한다.
- 표는 라운드 카드보다 얇은 행 구분선과 넉넉한 셀 여백을 사용한다.
- 상태와 위험도는 라임·코랄 색을 제한적으로 사용한다.

## 구현 원칙

- 먼저 현재 컴포넌트와 데이터 흐름을 읽고, 데이터 계산과 UI 렌더링의 경계를 확인한다.
- 변경은 가능한 한 dashboard HTML/CSS/표현 컴포넌트에 한정한다.
- 기존 차트를 새로 계산하거나 데이터 배열을 재작성하지 않는다.
- 모델이 만든 SVG 일러스트나 배경 이미지를 추가하지 않는다.
- 의미 없는 애니메이션을 넣지 않는다.
- `prefers-reduced-motion`, 키보드 포커스, 색 대비를 지원한다.
- 모바일 390px, 태블릿 768px, 데스크톱 1440px에서 레이아웃이 깨지지 않아야 한다.

## 검증 기준

구현 후 다음을 모두 확인하라.

1. 전체 기존 테스트와 빌드가 통과한다.
2. 여섯 개 내비게이션 화면이 모두 열린다.
3. “시장 전망”에서 SVG 또는 canvas 차트 2개가 실제 크기 0이 아닌 상태로 표시된다.
4. 두 그래프의 모든 시리즈와 범례가 유지된다.
5. tooltip과 탭 전환이 동작한다.
6. 기존 예측값과 원본 데이터 파일의 diff가 0이다.
7. 시각 변경 파일과 데이터·로직 파일의 diff를 분리해 보고한다.

완료 보고에는 다음만 간결하게 제시하라.

- 변경한 UI 영역
- 기능·데이터 보존 확인
- 그래프 2개 렌더링 확인
- 테스트·빌드 결과
- 수정한 파일 목록
