# Dashboard Research Intelligence v6

작성일: 2026-07-31

대상: GitHub Pages 운영 대시보드

범위: 데이터베이스·예측 산식·확률은 변경하지 않고 UI와 탐색 기능만 개선

## 1. 전체 감사 결론

현재 사이트는 홈 브리핑, 예측 목록, 질문 비교, MY RADAR, 시점 조회,
캘린더 저장, 메모, 데이터 상태, 캘리브레이션까지 이미 제공한다. 메뉴나
독립 기능을 계속 늘리면 사용자가 핵심 예측을 읽기 전에 인터페이스부터
학습해야 하는 문제가 생긴다.

이번 단계는 새 페이지를 추가하지 않고 다음 세 가지 기존 흐름을 깊게 만든다.

1. 상세 화면에서 `예측값이 왜 달라졌는지`를 회차 이동 즉시 읽는다.
2. 과거 혁신 사이클 그래프를 마우스·터치·키보드로 비교한다.
3. 예측 목록을 표 또는 카드로 바꾸고, 선택한 보기 방식을 다음 방문에도 유지한다.

## 2. 공식 제품 벤치마크에서 가져올 원칙

### Mistral AI

- 참고: https://mistral.ai/
- 한 뷰포트에 하나의 큰 이야기와 명확한 다음 행동을 배치한다.
- 움직임은 장식보다 현재 맥락과 탐색 방향을 설명하는 데 사용한다.
- 적용: 별도 대형 섹션을 추가하지 않고 기존 상세·그래프의 핵심 변화만 강조한다.

### Linear

- 참고: https://linear.app/now/how-we-redesigned-the-linear-ui
- 참고: https://linear.app/docs/display-options
- 시각 잡음을 줄이되 헤더·필터·보기 옵션의 계층은 분명하게 유지한다.
- 사용자가 선택한 정렬·그룹·레이아웃을 뷰별로 기억한다.
- 적용: 예측 목록에 간결한 TABLE/CARDS 전환을 추가하고 현재 기기에 저장한다.

### Mercury

- 참고: https://mercury.com/blog/march-2026-product-updates
- 자동 갱신 차트에 기간 비교와 “왜 바뀌었는가” 설명을 결합한다.
- 적용: 예측 상세 회차에 이전 회차 대비 확률·구간·출처 변화를 구조화한다.

### Ramp

- 참고: https://ramp.com/platform
- 전체 데이터를 나열하기보다 예외와 사용자가 확인해야 할 지점을 우선한다.
- 적용: 회차 변화의 크기를 `유지 / 소폭 조정 / 의미 있는 재평가 / 큰 폭 재평가`
  로 요약한다.

### Koyfin

- 참고: https://www.koyfin.com/
- 대시보드와 워치리스트를 사용자 관점에 맞게 바꾸면서도 전체 맥락을 잃지 않는다.
- 적용: 데이터는 동일하게 유지하고 표현 레이아웃만 사용자 선택으로 바꾼다.

### TradingView

- 참고: https://www.tradingview.com/support/solutions/43000746464-getting-started-with-supercharts/
- 참고: https://www.tradingview.com/support/solutions/43000745825-mastering-the-tradingview-watchlists/
- 비교 차트, 고정 판독값, 저장되는 레이아웃, 키보드 탐색을 하나의 흐름으로 묶는다.
- 적용: 과거 혁신 사이클에 시리즈 스포트라이트와 고정 월별 판독기를 추가한다.

## 3. 구현 블루프린트

### A. Evidence Delta

질문 상세에서 회차를 선택하면 기존의 확률·출처·근거 본문 위에 이전 회차 대비
변화를 표시한다.

구성:

- 변화 수준: 첫 기준선 / 확률 유지 / 소폭 조정 / 의미 있는 재평가 / 큰 폭 재평가
- 확률 변화: 부호를 포함한 `%p`
- 80% 신뢰구간: 이전 범위에서 현재 범위로 이동
- 출처 수: 같은 산출 방법일 때만 이전 → 현재와 증감
- 모델 또는 방법: 동일 여부와 현재 방법
- `이전 회차와 근거 나란히 보기` 버튼

원칙:

- 데이터가 없으면 `null`, `NaN`, `undefined` 대신 `기록 없음` 또는 `첫 기준선`을 쓴다.
- 산출 방법이 달라진 회차는 출처 집계 기준이 다를 수 있으므로 수량 증감을 계산하지 않는다.
- 자동 요약을 위해 새 예측이나 가짜 근거를 만들지 않는다.
- 비교 패널은 사용자가 펼쳤을 때만 표시하고 기본 본문 높이는 늘리지 않는다.
- 최신 회차뿐 아니라 사이드바에서 선택한 모든 R2 이상 회차에 동일하게 적용한다.

### B. Analog Explorer

과거 혁신 사이클 그래프를 기존의 일회성 hover tooltip에서 지속형 탐색기로 바꾼다.

구성:

- 전체 또는 개별 시대를 강조하는 `SPOTLIGHT` 버튼
- 포인터 이동·터치·좌우 화살표·Home·End 탐색
- 선택한 M+월과 실제 연월, 정규화 지수를 그래프 아래 고정 표시
- AI 현재 월을 기본 커서 위치로 사용
- 선택 시리즈는 선 굵기와 불투명도로 강조하고 다른 선은 낮춘다.

원칙:

- 터치 환경에서는 hover에 의존하지 않는다.
- SVG에 `role`, `tabindex`, 선택 월을 포함한 `aria-label`을 제공한다.
- 전체 선택 시에도 판독 영역을 과도하게 길게 만들지 않도록 반응형 그리드를 사용한다.

### C. Research Display Modes

예측 목록 상단 컨트롤에 `TABLE / CARDS` 보기를 추가한다.

구성:

- 데스크톱에서 표와 카드 레이아웃을 즉시 전환
- 두 보기 모두 같은 필터·정렬 결과와 동일한 질문 액션 사용
- 보기 선택은 로컬 UI 상태 v4에 저장
- 모바일은 공간 효율을 위해 항상 카드로 유지

원칙:

- 검색어는 저장하지 않는다.
- 필터 초기화는 필터와 정렬만 초기화하고 사용자의 보기 취향은 유지한다.
- 카드 모드가 데이터를 축약하더라도 확률, 직전 대비, 판정 시계, 테마,
  MY RADAR, 비교, 상세 이동은 모두 유지한다.

## 4. 시각·반응형 기준

- 새 컨트롤은 기존 warm-white, ink, orange, amber 체계만 사용한다.
- 새로운 그라디언트나 독립 색상 체계를 만들지 않는다.
- 44px 내외의 터치 영역과 명확한 포커스 링을 유지한다.
- 800px 미만에서는 TABLE/CARDS 토글을 숨기고 카드 목록만 표시한다.
- Evidence Delta 비교 본문은 데스크톱 2열, 모바일 1열로 배치한다.
- `prefers-reduced-motion`과 사이트의 움직임 최소화 설정을 그대로 존중한다.

## 5. 구현하지 않을 항목

- 서버 알림, 계정, 클라우드 메모, PWA: 정적 GitHub Pages 구조 대비 복잡도가 크다.
- 예측값 자동 재계산: 이번 작업은 UI 범위이며 기존 파이프라인이 담당한다.
- 새로운 캘리브레이션 필터: 해결된 표본이 충분히 쌓인 뒤 구현하는 편이 정확하다.
- 장식용 3D·과도한 패럴랙스: 정보 판독성과 모바일 성능을 해칠 수 있다.

## 6. 검증 계획

1. 자기완결 HTML과 기존 크기 예산을 확인한다.
2. UI 계약 테스트에 v6 텍스트·상태·핵심 함수 이름을 추가한다.
3. 전체 Python 테스트를 실행한다.
4. 실제 운영 데이터로 대시보드를 재생성한다.
5. 데스크톱과 모바일에서 상세 회차 비교, Analog Explorer, 목록 보기 전환을 확인한다.
6. 마우스·터치·키보드와 콘솔 오류를 함께 점검한다.

## 7. 완료 기준

- 사용자가 회차를 바꾸면 3초 안에 무엇이 달라졌는지 읽을 수 있다.
- 과거 사이클 그래프를 hover 없이도 탐색할 수 있다.
- 예측 목록의 보기 방식이 새로고침 후에도 유지된다.
- 기존 예측값, 데이터 원본, 메뉴 구조, 비교·메모·캘린더 기능에 회귀가 없다.
